# Week 1, Day 1: How the web works

*2026-10-26 evening to 2026-10-27*

## Plan

Understand what happens when a browser loads mi-hotel.ca, using the terminal and dev tools.

## What I did

Every step used my own site, mi-hotel.ca, as the specimen:

- **`dig`:** found the DNS chain: `www` is a CNAME to Wix, which resolves to Cloudflare's IP `172.66.3.8`. The nameservers are GoDaddy's.
- **`curl -sI`:** saw a `301` redirect from HTTP to HTTPS, read the headers, and noticed that Cloudflare (Toronto, "YYZ") answers in front of a Wix origin in Virginia.
- **`curl -sL | head`:** read the raw HTML and found that the site uses **Wix's default favicon**. Added this to the site audit.
- **A 404 test:** a made-up path returns `404`, and the response included `set-cookie` headers.
- **`ipconfig`, `ifconfig.me`, `whois`:** compared my private and public IPs; my ISP is Rogers.
- **`traceroute`:** 9 hops to the site in about 16 ms. Discovered my home network has **double NAT** (two routers).
- **A cookie experiment with httpbin.org:** watched a cookie get set, stored in a jar file, and sent back, then forged one (`role=admin`) to see why servers must never trust cookie contents.
- **TLS inspection:** mi-hotel.ca uses a 90-day **Let's Encrypt** certificate over TLS 1.3.

## Mistakes and what they taught me

- `https//` (missing colon) made curl try to resolve a host called `https`, and `-s` hid the error. Lesson: **use `-sS`**.
- I typed a URL with no `curl` in front. Lesson: the first word of a shell line is the program to run.
- `00.241...` instead of `99.241...` accidentally showed me the reserved `0.0.0.0/8` block, which turned out to be useful for Week 2.
- After the cookie experiment I deleted `jar.txt`. Lesson: think about what belongs in Git, and **never commit personal data** like my IP.
